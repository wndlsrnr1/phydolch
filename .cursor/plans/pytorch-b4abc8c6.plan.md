# 파이토치 튜토리얼 친절하게 만들기 계획 (수학 공식 유지)

## 1. 분석: 무엇이 문제인가?

- **문제점**: 현재 내용은 수학 공식과 코드 구현 사이의 연결고리가 부족합니다. 공식이 왜 필요한지, 코드의 어느 부분과 대응되는지에 대한 설명이 없어 개발자에게는 암호처럼 느껴질 수 있습니다.
- **대상 독자**: 고등학교 수준의 수학(행렬, 벡터, 기본 통계) 지식을 갖춘 중급 백엔드 개발자.
- **목표**: 수학적 정확성을 유지하되, 모든 공식을 코드와 직접 연결하고 직관적인 비유를 통해 "왜 필요한지"를 설명하여 친절함을 더합니다.

## 2. 개선 전략: 어떻게 바꿀 것인가?

- **공식 = 코드 매핑**: 모든 수학 공식 바로 옆에, 그 공식의 각 항이 파이토치 코드의 어떤 변수나 함수에 해당하는지를 명시적으로 보여줍니다.
- **Why-First 접근**: "왜 이 수학이 필요한가?"라는 질문을 먼저 던지고, 문제를 해결하는 코드를 보여준 뒤, "이 코드의 원리를 수학적으로 표현하면 바로 이 공식입니다"라고 설명하는 흐름을 채택합니다.
- **개발자 친화적 비유 강화**: 백엔드 개발 경험(e.g., 데이터 가중합, 성능 최적화, A/B 테스트)에 빗대어 수학 공식의 의미를 설명합니다.
- **Jupyter Notebook 수학 서식 준수**: 모든 수학 공식은 `.ipynb` 파일의 마크다운 셀 내에서 LaTeX 문법을 사용하여 작성합니다. 인라인 공식은 `$...$`로, 블록 공식은 `$$...$$` 또는 `\begin{...}...\end{...}` 형식으로 정확하게 표현합니다.

## 3. 실행 계획: 구체적으로 무엇을 할 것인가?

### 1단계: `00_Math_Foundations.ipynb` 수정

- **'행렬곱' 섹션**: 행렬곱 공식 `$Ax = x_1 a_1 + x_2 a_2$`를 유지합니다.
    - **추가할 내용**: 이 공식 바로 아래에 파이토치 코드로 공식을 증명합니다.
      ```python
      # 코드 예시: 공식이 실제 코드와 같다는 것을 보여주기
      A = torch.tensor([[2., 1.], [1., 3.]])
      x = torch.tensor([2., 3.])
      
      # 수학 공식 Ax
      result1 = A @ x
      
      # 수학 공식 x_1*a_1 + x_2*a_2
      result2 = x[0] * A[:, 0] + x[1] * A[:, 1]
      
      # 두 결과는 완전히 동일합니다.
      print(f"A @ x 결과: {result1}")
      print(f"선형결합 결과: {result2}")
      ```

    - **비유**: "API에서 받은 여러 데이터를 각기 다른 가중치(x)로 조합하여 최종 사용자 점수를 계산하는 로직과 같습니다."

- **'SVD' 섹션**: `$A = U\Sigma V^\top$` 공식을 유지합니다.
    - **추가할 내용**: `U, S, Vt = torch.svd(A)` 코드 결과와 공식을 1:1로 매핑합니다.
      - `$U$`: 코드의 `U` 텐서. "결과를 보여줄 좌표축"
      - `$\Sigma$`: 코드의 `torch.diag(S)` 텐서. "각 좌표축 방향으로 얼마나 늘릴지(중요도) 결정하는 값"
      - `$V^\top$`: 코드의 `Vt` 텐서. "입력 데이터를 어떤 좌표축에서 바라볼지 결정하는 회전"
    - **핵심 설명**: "SVD는 복잡한 변환(행렬 A)을 '회전 → 크기조절 → 다시 회전'이라는 세 단계의 간단한 동작으로 분해하는 것입니다."

### 2단계: `00a_Calculus_Foundations.ipynb` 수정

- **'Gradient Descent' 섹션**: `$w_{\text{new}} = w_{\text{old}} - \eta \nabla L(w)$` 공식을 유지합니다.
    - **추가할 내용**: `optimizer.step()`이 내부적으로 이 공식을 어떻게 실행하는지 설명합니다.
      - `$w_{\text{old}}$`: 업데이트 전 파라미터 (`layer.weight.data`)
      - `$\nabla L(w)$`: `loss.backward()`로 계산된 그래디언트 (`layer.weight.grad`)
      - `$\eta$`: 옵티마이저에 설정한 학습률 (`optimizer.param_groups[0]['lr']`)
      - `$w_{\text{new}}$`: `optimizer.step()` 실행 후 업데이트된 파라미터.
    - **핵심 설명**: "옵티마이저가 파라미터를 업데이트하는 것은, 결국 손실을 가장 가파르게 줄일 수 있는 방향으로 정해진 보폭(learning rate)만큼 파라미터를 이동시키는 과정입니다. 이 공식은 그 과정을 요약한 것입니다."

### 3단계: `00b_Probability_Statistics_Foundations.ipynb` 수정

- **'MLE와 손실 함수' 섹션**: Negative Log-Likelihood 공식 `$\text{Loss} = -\log L(\theta | \mathbf{x})$` 와 CrossEntropy 공식 `$-\sum y_k \log \hat{p}_k$` 를 모두 유지합니다.
    - **추가할 내용**: 두 공식이 왜 같은 의미인지 설명합니다.

      1.  "MLE의 목표는 주어진 데이터(`x`)가 나올 확률(`L`)을 가장 높이는 파라미터(`θ`)를 찾는 것입니다."
      2.  "확률을 최'대'화하는 것은, 로그 확률을 최'대'화하는 것과 같고, 이것은 다시 마이너스 로그 확률을 최'소'화하는 것과 같습니다."
      3.  "분류 문제에서 이 '마이너스 로그 확률'을 계산하는 식이 바로 CrossEntropy Loss입니다. `$\hat{p}_k$`는 모델이 예측한 정답일 확률이므로, `-log($\hat{p}_k$)`는 정답 확률에 대한 마이너스 로그 확률과 정확히 일치합니다."

    - **코드 연결**: `F.cross_entropy`가 이 공식을 어떻게 한 번에 계산해주는지 보여줍니다.
