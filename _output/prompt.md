# 교과서형 설명 보강 파이프라인 프롬프트

이 프롬프트는 “Plan → Analysis → Enhancement Plan → Execution → Validation” 흐름을 강제해, 기계적으로 서술된 텍스트를 교과서 수준의 친절한 설명으로 재구성합니다.

---

## 0. 목적과 핵심 원칙
- 입력 텍스트의 기호‧변수 의미를 빠짐없이 정의한다.
- 공식이 등장하기 전에 “왜 필요한가 / 어디서 나왔는가”를 설명한다.
- 직관 → 수식(유도) → 구체적 예시 순서로 독자를 안내한다.
- Step 0, Step 1 …처럼 단계별 제목과 목표를 명확히 제시한다.
- 이론 ↔ 실전, 이전 ↔ 다음 개념 간 연결고리를 드러낸다.

---

## 1. 입력 형식
```
<<TEXT_TO_ENHANCE>>
```
- 텍스트는 Markdown 또는 일반 문장 형태.
- 가능한 한 원문 전체를 제공해 흐름 단절을 방지합니다.

---

## 2. 전체 작업 흐름 (Plan 고정)
1. **Prompt A (Analysis)** – 원문 진단
2. **Prompt B (Enhancement Plan)** – 문제별 해결 전략 설계
3. **Prompt C (Execution)** – 개선 텍스트 작성 및 검증
4. **Validation** – 체크리스트로 품질 점검, 잔여 리스크 제시

> ⚠️ Plan 없이 바로 Execution 단계로 넘어가지 않습니다.

---

## 3. Prompt A — 텍스트 진단용
입력: `<<TEXT_TO_ENHANCE>>`

지시사항:
1. 전체 내용을 3~5문장으로 요약한다.
2. 문제점을 표나 목록으로 정리한다.
   - 기호/변수 정의 누락
   - 공식·정의 앞 맥락 부재
   - 단계/흐름 불명확
   - 직관·예시 부족
   - 개념 간 연결 단절
   - 기타 발견된 문제
3. 유지해야 할 장점을 정리한다.
4. 가장 시급한 개선 목표 3가지 이상을 이유와 함께 제시한다.
5. 가능하다면 좋은 레퍼런스(교과서적 설명)와의 차이를 한두 문장으로 비교한다.

출력 템플릿(권장):
```
- Summary:
- Issues:
  1. ...
- Strengths:
- Priority Fixes:
- Reference Gap:
```

---

## 4. Prompt B — 보강 계획 수립용
입력: Prompt A 결과

지시사항:
1. “문제 → 해결 전략 → 기대 효과” 구조로 우선순위별 작업 항목을 작성한다.
2. 새롭게 추가해야 할 구조(예: Step 0, 표, 시각 자료 등)를 명시한다.
3. 원문의 장점을 어떻게 유지/강화할지 덧붙인다.
4. Plan에 맞춰 Execution 단계가 따라야 할 순서를 정리한다.

출력 예시:
```
Overall Strategy:
- ...

Action Items:
1. Problem ...
   - Fix ...
   - Impact ...
2. ...

Preserve & Amplify:
- ...

Execution Order:
1. Step 0 ...
2. ...
```

---

## 5. Prompt C — 실행 및 자체 검증용
입력:  
- `<<TEXT_TO_ENHANCE>>`  
- Prompt B에서 도출된 보강 계획

지시사항:
1. 계획된 순서대로 텍스트를 재작성한다.
2. 각 단계(예: Step 0, Step 1 …)의 목표를 제목으로 명시한다.
3. 모든 기호·변수를 등장 즉시 정의하고, 공식 전에 맥락을 설명한다.
4. 직관 설명 → 수식 유도 → 사례/숫자 예시 → 요약 순서를 유지한다.
5. 문체는 원문과 일관되게 유지하며, 불필요하게 장황하지 않게 조정한다.
6. 변경 사항을 이전/이후/이유 형식의 표로 정리한다.
7. 품질 체크리스트 각 항목의 충족 여부와 근거를 보고한다.
8. 남은 리스크나 후속 제안을 기록한다(필요 시).

출력 구조:
```
## Enhanced Text
...

## Change Log
| Before | After | Reason |
| --- | --- | --- |
| ... | ... | ... |

## Quality Checklist
- [x] 모든 기호/변수 정의: ...
- [x] 공식 앞 맥락 제시: ...
...

## Residual Risks / Next Steps
- ...
```

---

## 6. 품질 체크리스트 (Validation 단계에서 사용)
- [ ] 모든 기호와 변수가 등장 즉시 정의되었다.
- [ ] 공식이나 정의 앞에 “왜 / 어디서” 맥락이 제시되었다.
- [ ] Step 0 → Step 1 → … 구조가 명확하다.
- [ ] 직관 → 수식 → 예시 → 요약의 흐름이 유지된다.
- [ ] 최소 한 가지 구체적 수치 또는 사례가 포함되었다.
- [ ] 이전/다음 개념 또는 실전 코드와의 연결이 명시되었다.
- [ ] 변경 사항 표가 포함되었고, 각 변경의 이유가 설명되었다.
- [ ] 남은 리스크나 추가 제안이 필요 시 기록되었다.

---

## 7. Before / After 예시

```
Before:
H(X) = -∑ p_i log p_i

After:
Step 0: 기호 정리
- X: 결과를 만드는 확률변수
- x_i: X가 가질 수 있는 i번째 사건
- p_i = P(X = x_i): 사건 x_i가 일어날 확률

Step 1: 왜 이 공식을 쓰는가?
- 사건이 일어났을 때 느끼는 “놀라움(정보량)”을 수치화하고 싶다.
- 놀라움이 클수록 정보량이 크다 → log(1/p_i)

Step 2: 평균 정보량 정의
- 사건별 정보량 I(x_i) = -log p_i
- 엔트로피: 가능한 모든 사건의 정보량을 기대값으로 평균낸 값
- H(X) = -∑_{i=1}^n p_i log p_i

예시: 공정 동전(p=0.5) vs 편향 동전(p=0.9)에 대해 각각 H(X)를 계산해 차이를 비교한다.
```

---

## 8. 최종 산출물 요약
Prompt C 실행 결과물에는 반드시 다음이 포함되도록 한다.
1. 개선된 본문
2. 변경 사항 요약 표
3. 품질 체크리스트 충족 여부와 근거
4. 남은 리스크 또는 후속 제안(있다면)

---

## 9. 활용 팁
- 긴 문서는 섹션별로 Prompt A → B → C를 반복 실행한다.
- 그래프나 그림이 필요한 경우 설명 텍스트에 “(그림)” 등 표시를 남겨 후속 작업으로 분리한다.
- 이미 친절한 부분은 불필요하게 늘이지 않고 유지한다.

---

이 프롬프트 묶음을 그대로 활용하면, 항상 “계획을 먼저 세우고 → 문제를 진단하고 → 해결 전략을 설계하고 → 실행 및 검증”하는 파이프라인을 재현할 수 있습니다.
